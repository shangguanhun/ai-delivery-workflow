# Dot 的用法与边界

“Dot”在本库中表示部署者选择的协调与核查入口。它可以是具备相应工具的助手，也可以是人工协调会话；本库不声称任何特定账号一定具备跨会话读取、任务发送、仓库写入、电脑控制、后台监听、永久记忆或免费调用能力。

## 适合交给 Dot 的工作

| 工作 | 输入与产出 | 必须核对 |
| --- | --- | --- |
| 资料边界/脱敏核查 | 原作者的确切候选、授权范围；返回疑点和需排除材料 | 文件字节、元数据、链接与授权，不读取无关记忆或私聊 |
| 版本与可读性核对 | 固定版本/清单与指定接收方；返回实际可读结果 | 发出、接收、环境可读分别证明 |
| 原文转交 | 作者定稿及用户边界；向已核收件人转同一内容 | 消息授权、收件身份、平台发送是否会自动启动回合 |
| 独立复核 | 确切候选、风险和独立上下文；结论及反例 | 是否作者/采用者；普通核对不能冒称独审 |
| 私有建仓与安全迁移 | 已审候选、明确建仓/写入/迁移授权 | 净化文件集、空新仓、私有可见性、旧入口回退与目标加载 |

Dot 不替网页作者写协作方法、产品设计、规则定稿或另一套任务拆分。发现错漏时提出具体反例，交原作者修订再核身份。可以机械提取、比对、包装或准确转录，不能把语义改写藏在“整理”里。

## 第一次使用只查当前所需能力

先确认所需的读取/发送/建仓/检查动作是否有真实支持工具与相应授权，核工具是否会修改外部状态或激活任务。只读查询、发送草稿、实际发送、触发运行不是同一动作。模型和费用以当前工具/服务证据为准，不从名称或聊天额度推测。

若只有聊天能力，就交付可复制正文给用户转交；不声称已经通知。附件只返回正文引用却拿不到文件时，可在授权范围内索取确切文件原文或采用其他受支持渠道，但不反复做无变化搜索，也不为可达性公开私有仓库。

## 独审与采用不能混为一谈

资料范围检查、哈希比对和脱敏核查可以是发布前的普通核对，但不能代替正式风险独审。Dot 若正式充当本候选独审者，就不能再采用同一候选；Dot 若负责授权建仓/发布，应读取另一位合格独审者的确切结论。沿已有参与者分配即可，不新增专职审批层。

所谓独立，取决于职责、作者/采用关系与支持的上下文，不是另叫一个模型名字。作者自检保留，但不能贴上独审标签。

## 原文交接的最小做法

保留作者的候选身份、全文、授权与暂停边界。核查备注在正文外；需要脱敏时由原作者出可转版本，不向不安全接收方发送原文再补救。原文过长可分批原样转录并标路径/顺序，不能以摘要冒充完整文件。

用 [转交模板](../templates/relay-note.md) 复用已有记录，不另建收件台账。原作者/消费者/审查者在获准范围能直交时，Dot 不必成为每步必经中转。

## 通知、等待与暂停

“通知规则版本可用”不能含糊地变成“恢复所有任务”。发送前核目标和当前停点；若发送会自动激活目标且恢复未获授权，不直接发送，保留待用户安排的通知正文。

可靠完成通知可用就复用；同一游标或状态没有新事实时退避，不连续询问“完成了吗”。无独立工作时安全结束协调回合，先确认宿主不会因此取消子任务或丢回执。没有可靠通知时采用获准的有界后续检查，不能凭空承诺后台监听，也不私建定时器。
