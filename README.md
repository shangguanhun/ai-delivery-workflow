# 以结果为中心的 AI 协作

把用户目标变成可以打开、操作、退出并继续的结果，而不是一串无人收尾的模块报告。

这是一个通用方法与执行规则候选仓库，不是运行中的代理平台。它不自动创建任务、连接账号、选择模型、监听后台或迁移项目。当前状态见 [STATE.md](STATE.md)，版本见 [VERSION](VERSION)。首次建仓拟采用私有可见性；未来公开须另行确认范围、权利和许可，见 [RIGHTS.md](RIGHTS.md)。

## 工作方式

用户提出目标/反馈并控制授权与暂停。获授权的网页版 Chat 做产品分析、任务包与规则正文；Dot 做可选的资料核查和原文交接；本地主控核实际版本与依赖、风险、采用；一名主要实现者把完整里程碑做到底。必要独审由独立者完成，实际产品接受权不从角色名推定。

这是责任划分，不是必须开齐所有角色的代理编队。小而明确的任务可以由一个 AI 完成；工具缺失时用用户转交或同会话内的清楚步骤，不为模仿架构新增服务。

## 核心约定

一位主要实现者对完整可体验结果负责，包括实现、自检、整合、修复和实际入口。独立且确有收益才并行，不能按文件或模型档位把任务拆碎。需求明确不等于复杂度低，按整体耦合、风险、工具与交付总成本选择能力，具体模型由部署者/项目配置。

开发同时准备验收材料与真实操作路径。两轮无实质成功要作方法取舍，不是两轮必成。优先现有可靠通知，无新信息退避；安全结束无效协调回合不取消任务，也不放弃接收。

必要独审、真实运行、存档安全、用户暂停和权限拒绝保持。源码绿、哈希一致或作者自检不等于体验完成。最后交给用户可用入口、版本、操作和限制，不能只留下证据目录。

## 内容边界

本库只含通用正文、空白必要模板、虚构例子与本候选作者自检说明。不含旧仓库历史、个人身份/账号/真实任务标识、项目专属规则、真实进度、私密会话、凭据或个人模型默认。

[项目模板](templates/project-AGENTS.md) 只在各自项目中填写；[网页入口模板](templates/web-public-project-instructions.txt) 填入部署者真实采用的版本后使用。占位内容不能启动任务，也不能声称已加载。

## 文件包如何核对

交付时的外部 JSON 清单列出本仓库每个文件的相对路径、UTF-8 字节数和 SHA256；它位于归档之外，因此能覆盖仓库全部文件而没有自哈希例外。归档本身另有 SHA256。该清单证明字节身份，不证明作者身份、内容安全、独审或采用。

所有仓库文件为 UTF-8、无 BOM、LF 行尾。保留原规则加载路径不等于把候选直接覆盖到现有项目；先审查、授权采用，再在安全节点切换。详细检查方法见快速开始。
