# 阶段 3：最小充分证据与必要独审

规则版本：`portable-collaboration-v1`；本节修订：`verification-convergence-r1`。检查、QA、取证与独审前读取；实际运行/派发还需阶段 2。预期来自用户、已批准设计/合同或有依据推导，不从实现输出反推。

## 风险与检查范围

| 风险 | 范围和必要证据 |
| --- | --- |
| 高 | 治理规则、权限/信任、安全隐私、持久数据/schema/迁移、跨责任或外部接口、部署/外部状态、验证器/接受逻辑、不可逆/广泛/影响不明变更：相关正反例、失败恢复及必要独审 |
| 中 | 稳定接口内、有界普通行为变更：针对检查及最近的集成/运行/视觉回归，不默认全套 |
| 低 | 无行为、数据、权限或共享合同影响的文案/格式/机械修改：差异及最便宜直接核对，不习惯性跑套件或整树哈希 |

验证前沿原任务记录明确本轮问题、真正阻塞条件、相称范围和停止条件；已有合同覆盖就引用，不另建表或逐项审批。阻塞须对应本批核心使用/体验承诺、安全、存档/数据、权限、外部合同、有依据的新增风险或必要证据/独审缺口。非阻塞细节记录后，不拖住已满足约定门槛的可用增量。

重大跨模块集成、正式发布和约定主要可用阶段保留适用独审。辅助修补按真实影响分类，不因名称或服务重大项目就升级；涉及本节高风险面或危及关键状态完整性的变化，及时开展相称定向检查与风险控制；必要独审在最早具备连贯风险输入的候选上开展，并在采用该变化或下游实质依赖该变化之前完成。不默认逐微小改动单独独审，也不为等待里程碑而延后真实风险或决策所必需的独审；其余有界修补只做相称检查。新风险或反例只扩大相关范围。

## 真实入口与证据类别

完整运行前预检版本、材料/数据、工具与操作可达。按本轮主张走主要操作、实际结果、失败/退出和保存/继续，覆盖必要邻近回归；真实用户入口观察、模拟/夹具结果及工具自检各自限定证据范围，不能单凭后两者宣称真实入口已验收。视觉看目标尺寸和关键局部，连续行为看相称连续画面与操作，声音实际听音；源码、文字状态、draw 计数或孤立截图不能替代。

普通获取/成长等自然体验，与前提具备后的功能、表现、保存验证分开。优先合法积累进度；自然窗口结束或随机材料未齐，保留已观察结果及对应未验范围，不无限等待，不把截断样本当完整链。获准隔离夹具/条件入口须标来源与范围，不能证明普通取得或真实用户体验；不得擅改概率、时间规则或注入真实档。

区分产品缺陷、采集工具故障、环境/交接缺口和未运行。工具修复沿原授权有界进行，先证明可达再跑全程。若连续工作主要在修工具、随机等待或重复采集，却未带来相称有效证据或产品风险降低，主要实现者应在安全节点收敛路线：评估已有获准的直接操作或更简单方法，明确剩余问题与停止条件，停止无收益的工具扩建/采集，不为报告或通过数继续。必需证据仍缺时保留相应主张未验及下一步，真实产品失败不降格，停采不等于通过。受限测试者交回作者，不私改断言、源码、权限或验收基线。

数值主张核单位、分母、缺失、精度、样本和不确定性，保留不利结果。合成与真实数据分开；分析图表不自动采用参数或证明趣味。用户感觉和模型判断不能由通过率代替。量化目标/阶段进度时，沿已约定验收清单、分母与权重，按当前有效证据计入已满足项；范围变化说明分母，不用通过数、消息数或旧批次进度替代。

## 版本与复用

正式冻结或交付时保留可还原的 Git 快照/提交及相关未提交、未跟踪、暂存内容，非 Git 用有界清单及对应原件；结论须对应确切输入。原记录给出输入、环境、方法、结果和必要证据指针。相关字节、依赖、环境、方法和验收前提均不变，且门槛允许时应复用；变化后只重查受影响主张。部分结果可核对对应状态后接续，不因轮次或窗口结束重做有效部分；连续体验、保存/恢复等跨段主张仍须满足其时序与状态证据，不能拼接不相容记录冒充完整验证。强制原文/身份核验与真实风险复核不省略。

哈希只证明身份，适用于交接、冻结、重载、供应链或明确漂移风险，不证明权限、来源权利或运行质量。不重复整仓扫描以制造进度，不把旧候选 PASS 搬到新字节上。

## 独立性与接受

独审针对确切输入、风险面与主张。作者/采用者不能自审，审查者不代修或采用。风险触发的必要独审不以设置独立 QA 里程碑为前提，相关范围可合批，时机按本节高风险要求执行。按约定需要完整独立 QA 的里程碑，在同版冻结的整合候选上完成约定验收范围的完整独立 QA；两种门槛分别满足，不能相互替代。不逐小修机械重启全套验收、冻结或主控转发链，反例直交原主要实现者；合批或新候选不重置失败历史及未过门槛。后续变化按新增风险和受影响主张复核，不拿旧 PASS 覆盖新字节。复用同一合格独审者，保留失败及相邻回归；新增审查者须有不同风险或原审查者不适用的理由。普通子调用或更强模型不自动具有独立性。

Dot 的资料脱敏核查不是正式独审。若它正式承担独审，则不能采用同一候选；若它承担建仓、发布或规则采用，须有另外合格、独立的审查结论。责任可沿已有人员落实，不为此增加管理链。

原记录只需输入身份、风险/主张、审查者独立性、结论及必要替换依据；工具必填项照填，不增公共固定模板。问题已被充分回答且必要门槛满足，就结束本轮验证，按阶段 4 交付可打开的入口、版本与限制。候选自检、独审、工程 QA、玩家观察与最终 ACCEPT 分开；暂停、权限、真实反例和未过门槛不因收敛而取消或改写为通过。
