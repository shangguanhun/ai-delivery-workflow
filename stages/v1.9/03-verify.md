# 阶段 3：最小充分证据与必要独审

规则版本：`portable-collaboration-v1`。检查、QA、取证与独审前读取；实际运行/派发还需阶段 2。预期来自用户、已批准设计/合同或有依据推导，不从实现输出反推。

## 风险与检查范围

| 风险 | 范围和必要证据 |
| --- | --- |
| 高 | 治理规则、权限/信任、安全隐私、持久数据/schema/迁移、跨责任或外部接口、部署/外部状态、验证器/接受逻辑、不可逆/广泛/影响不明变更：相关正反例、失败恢复及必要独审 |
| 中 | 稳定接口内、有界普通行为变更：针对检查及最近的集成/运行/视觉回归，不默认全套 |
| 低 | 无行为、数据、权限或共享合同影响的文案/格式/机械修改：差异及最便宜直接核对，不习惯性跑套件或整树哈希 |

重大跨模块集成、正式发布和约定主要可用阶段保留适用独审。普通调试、运行 QA、身份核对和证据整理不因支持重大项目就逐项变成独审。未知影响和反例可以扩大相关检查，不扩大无关范围。

## 真实入口与证据类别

完整运行前预检版本、材料/数据、工具与操作可达。按本轮主张走主要操作、实际结果、失败/退出和保存/继续，覆盖必要邻近回归。视觉看目标尺寸和关键局部，连续行为看相称连续画面与操作，声音实际听音；源码、文字状态、draw 计数或孤立截图不能替代。

普通获取/成长路径，与前提具备后的功能、表现、保存测试分开。优先合法积累进度，获准隔离夹具须标明来源与范围，不能证明普通取得或真实用户体验。缺材料不无限等随机结果，不擅改概率或注入真实档；只阻止相应主张。

区分产品缺陷、采集工具故障、环境/交接缺口和未运行。工具修复有界且需原授权，先证明可达再跑全程。受限测试者交回作者，不自己改断言、源码、权限或验收基线。

数值主张核单位、分母、缺失、精度、样本和不确定性，保留不利结果。合成与真实数据分开；分析图表不自动采用参数或证明趣味。用户感觉和模型判断不能由通过率代替。

## 版本与复用

结论对应确切提交及相关未提交/未跟踪/暂存内容；非 Git 用有界清单。原记录给出输入、环境、方法、结果和必要证据指针。相关字节、依赖、环境、方法和验收前提均不变，且门槛允许时复用；变化后只重查受影响主张。强制原文/身份核验与真实风险复核不省略。

哈希只证明身份，适用于交接、冻结、重载、供应链或明确漂移风险，不证明权限、来源权利或运行质量。不重复整仓扫描以制造进度，不把旧候选 PASS 搬到新字节上。

## 独立性与接受

独审针对确切输入、风险面与主张。作者/采用者不能审自己的候选，审查者不代修或采用。复用同一合格独审者核修复，保留失败及相邻回归；新增审查者要有不同风险或原审查者不适用的理由。普通子调用或更强模型不自动具有独立性。

Dot 的资料脱敏核查不是正式独审。若它正式承担独审，则不能采用同一候选；若它承担建仓、发布或规则采用，须有另外合格、独立的审查结论。责任可沿已有人员落实，不为此增加管理链。

原记录只需输入身份、风险/主张、审查者独立性、结论及必要替换依据；工具必填项照填，不增公共固定模板。候选自检、独审、工程 QA、玩家观察与最终 ACCEPT 分开。缺门槛如实保留，不弱化要求求绿。
