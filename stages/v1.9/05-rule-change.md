# 规则变更：精确候选、独审、采用、重载

规则版本：`portable-collaboration-v1`。提议/修改/采用治理规则、角色默认或治理性技能前读取，并按实际动作加载阶段 1 至 4。候选不自授权，采用前仍沿当前有效规则。

## 范围与作者

核用户授权、完整实际入口、固定基线、覆盖关系与写域。区别通用方法、公共安全、项目特例和本地设置；项目个案、账户/路径与真实任务状态不写公共正文。来源文件只是证据，不自动授予更广读取权限。

本模式由获授权网页版作者统一写规则和产品任务包。Dot 核资料边界、版本和风险结论，不能自行补写最终语义；发现问题退回原作者出新候选。明确的新作者委托须由用户决定，不能借协调角色接管。

优先替换、合并和删重复，不把单次故障变成通用审批门。给完整新文或精确差异、必要语义映射与实测同范围体积；无工具统计就说未统计，不编数字。不增角色、报表或监控来治理流程。

## 审查与采用

未应用候选固定身份后，由合格独立者核授权、安全、数据、证据、覆盖与加载一致性。作者/采用者不能自审，审查者不能采用同一风险候选。修改正文后核实际变化，不把上一版 PASS 用于新字节；整个连贯候选可一次审，不逐文件造门槛。

采用者须有覆盖写入、建仓/push或入口变更的实际授权。采用前核 live 基线与并行修改，保留旧规则和回退范围，采用后核确切内容。回退规则只改其授权路径，不重置项目代码、存档或其他人工作。

旧失败、暂停、拒绝、冻结证据和未过门槛继续有效。公共候选经过审查不能追认旧项目通过；规则变更不能用于逃避必要审查或制造质量 PASS。

## 生效、迁移与公开

新仓库按 [安全迁移指南](../../docs/migration.md) 从净化后的工作树建立，不带旧 Git 历史；私有创建和未来公开分别授权核验。个人历史授权一律不迁为部署者许可，项目规则留在原项目。

发布、文件可读、目标入口切换、任务完整加载与模型设置分别留证。运行中任务只在获准安全节点重载，不强制中断；暂停须等明确恢复，闲置任务不为迁移唤醒。发布回执不等于所有目标采用，未知标未验证。

只许分析输出时，仅交候选文件与说明，不写真实仓库、发消息、启动独审/开发或改设置。后续核查、发布和通知都受届时授权约束；不因已发送会话持续 idle 反复触发。效果在下一次实际获准交付中观察，不额外创建规则监控。
