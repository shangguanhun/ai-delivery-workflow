# 文件与账号交接

规则版本：`portable-collaboration-v1`。共享文件、仓库输入或声称另一环境能继续工作前读取；不是一般任务的必经审批。

## 范围与最小材料

在原任务说明用户授权来源、必要文件/确切版本、数据类别、发送与接收方、目的、权限和完成条件。实际账号信息仅存授权项目的私有记录，通用仓库不留。固定接收方不能替换为任意持链接者；同一人的不同账号也分别核权限。

只传任务所需材料。项目规则、运行配置、真实进度和原始日志原则上留原项目；确需交接时单独在相应授权范围内处理。凭证、会话和无关私密内容不发送。隐去姓名不代表其他元数据已无关联，检查标题、路径、时间、截图、版本历史和链接。

提交源码时给固定提交加相关未提交/待采用差异说明；不能把脏工作树冒充纯提交。无仓库访问可用获准的精确文件包和逐文件身份。完整哈希证明同一字节，不证明许可、接收可读或可以运行。

## 载体分别验证

| 载体 | 必须独立核实 |
| --- | --- |
| 项目附件/聊天附件 | 正确项目与可见范围，是否连带暴露会话和旧附件，接收方是否实际能读 |
| 文件库或 Library 类载体 | 引用/链接是否对接收方有效，能否在目标环境取得字节；发送方可见不算交付 |
| 资料空间/页面 | 项目共享是否真的包括指定页面和附件，不能预设全部可达或全部不可达 |
| 私有 Git 仓库 | 当前授权账号的读写权限、固定版本和必要文件；无权限不改公开、不擅邀协作者 |
| 实际执行环境 | 能否读取/解包、核版本、使用获准依赖、运行入口；本地服务/浏览器进度不会自动迁移 |

只在任务实际使用的载体上核查，不为未使用平台扫描全部账号。接收证据来自接收环境真实读取、工具回执或用户对相应访问的明确报告，不用上传成功代替。

## 接收、缺口与恢复

在原记录保留收到的版本、读取/运行结果、未知与具体缺失依赖。大量文件可用有界清单，关键规则、入口、必要素材和恢复输入须核足。只读未运行明确说只读，目标账号未验不能称迁移完成。

若某渠道不可用，选已有授权且官方支持的其他交付方式；真实权限拒绝不能绕过。重复发送前先核首次结果，不产生重复邀请或无声覆盖。保留源文件，接收失败不删除或停掉唯一来源。

规则库迁移另参 [迁移指南](../../docs/migration.md)。新的公共库只接收净化后的通用文件，不包含旧 Git 历史、项目例外或个人授权；接收后仍需独立采用与加载，不自动启动任务。
